## Player and authority contracts

The topology is:

    native Godot -> own per-PC 127.0.0.1 random-port bridge
                  -> Toast HTTPS player gateway
                  -> single Toast HEAT account/ledger owner
                  -> mutually authenticated HTTPS game authority on Harbinger

Players receive only a public CA certificate, Toast's actual server SPKI pin, an HTTPS origin and world ID. They do not receive Toast's authority client certificate/key or Harbinger's server key. Player HTTPS uses TLS 1.3, explicit CA trust, certificate hostname validation and SHA-256 SPKI pinning, with TLS session caching disabled. Wrong CA, hostname, pin or protocol fails closed. No certificate verification bypass exists. Leaf role/validity checks reject expired or wrong-role prepared service certificates. Rotation/revocation requires replacement of approved certificate/pin configuration; Stop/Start reloads it. No external auth provider is merged.

`player-gateway.cjs` handles POST `/api/player/v1/{health,login,logout,summary,admission,connect,state,input,disconnect}`. Every envelope is exactly `{world_id,request_id,data}` with a 64-hex request ID, agreed world and operation-specific data. Responses bind protocol `10six-player-https-v1`, request and world; snapshots bind the same world. Login calls the existing HEAT scrypt account verifier and issues its existing seven-day cookie with Secure, HttpOnly and SameSite=Strict. Players' cookies stay inside their in-memory bridge and travel only over verified HTTPS.

An admission is single use for 30 seconds. Connect requires the same active HEAT account session that obtained it. Each native state/input/disconnect requires both the native token and its owning HEAT cookie; another signed-in account cannot consume a ticket or use someone else's native token. Remote native tokens expire after 15 minutes. The bridge renews them through fresh HEAT admission/connection at most 60 seconds before expiry, preserving the same initial account, world and durable sequence/receipt. Godot receives a separate random local-only bearer, never the remote bearer. Each explicit Play launch has an eight-hour absolute limit, which automatic renewal cannot extend. Renewal occurs on state/input traffic and is serialized with other bridge operations; gaps earn no participation credit. Logout invalidates the HEAT session, causing its tickets/tokens to fail. Stop best-effort disconnects/signs out; if the network is unavailable, local secrets are discarded and server-side expiry still applies. Ordinary play continues across remote token rotation while the original HEAT cookie remains valid. At the eight-hour play limit, Stop game and Play starts a new explicitly requested session. Logout, session revocation, expired seven-day cookie or an account/world mismatch stops renewal; the native client clears its token and pending actions and displays the error. Sign in again when the HEAT session ends. Renewal never extends the HEAT session expiry or stores a password/cookie on disk.

The per-PC bridge is untrusted. It binds random loopback only, requires its exact Host, rejects browser Origin headers, limits native body size to 16 KiB, has at most four pending requests and 16 connections, and uses an additional in-memory single-use local admission. Only game intents enter the adapter: no profile override, credit counters, award list or arbitrary report is accepted. HEAT/authority durable sequence, generation, frame and receipt checks provide replay prevention and idempotency; a new transport request ID is not an award or input identity. Lost replies after commit remain retryable, and the native client retains that exact pending intent. Reconnect reconciles uncertain remote receipts. Existing 100 daily / 250 per accumulated hour / Chicago attendance rules and the two approved Visitor camp trophies are unchanged.

The gateway caps bodies at 16 KiB, headers at 8 KiB, concurrent requests at 32, concurrent sign-ins at four, connections at 64 and requests per socket at 128, with 10-second header/15-second request limits. Existing HEAT account throttles, session/account caps and adapter limits also apply. No browser cross-origin API is enabled.

Desktop JSON IPC is `{id,operation,data}`; operations are status, check, start, register (Toast only), login, play, stopgame, summary, logout, stop and shutdown. Commands are serialized with an eight-request queue and 16-KiB line limit. Replies expose status/public account/award views only. They never return passwords, cookies, tickets, bearers, authority credentials or private paths. This contract can be used by the earlier Harbinger C# shell; its source was unavailable on Toast, so that separate shell has not been integrated here. The v4 paired packages carry the same reviewed shared shell/backend instead.
